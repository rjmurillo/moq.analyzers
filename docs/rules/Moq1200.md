# Moq1200: Setup should be used only for overridable members

| Item     | Value |
| -------- | ----- |
| Enabled  | True  |
| Severity | Error |
| CodeFix  | False |

---

If Moq throws "Invalid setup on a non-virtual (overridable in VB) member" or
"Non-overridable members (here: ...) may not be used in setup / verification expressions",
you are calling `Setup` on a member Moq cannot override. Moq1200 reports this at build time.

## Runtime error this rule prevents

The text depends on your Moq version. Both forms mean the same thing.

Checked at Moq 4.2.1510.2205, 4.7.145, and 4.10.1:

```text
Invalid setup on a non-virtual (overridable in VB) member: {0}
Invalid verify on a non-virtual (overridable in VB) member: {0}
```

Moq replaces `{0}` with the expression. For example:

```text
Invalid setup on a non-virtual (overridable in VB) member: x => x.GetPrice("A1")
```

Checked at Moq 4.11.0, 4.18.4, and 4.20.72:

```text
Unsupported expression: {0}
Non-overridable members (here: {0}) may not be used in setup / verification expressions.
```

Moq replaces the first `{0}` with the expression and the second with the member. For example:

```text
Unsupported expression: x => x.GetPrice("A1")
Non-overridable members (here: PriceService.GetPrice) may not be used in setup / verification expressions.
```

Moq 4.7.145 and 4.10.1 throw the first form as `System.NotSupportedException`.
Moq 4.18.4 and 4.20.72 throw the second form as the same type.

`Verify` and `SetupSequence` produce the same error family. [Moq1210](Moq1210.md) reports `Verify`.
[Moq1207](Moq1207.md) reports `SetupSequence`, including Moq 4.10.1, where the call does not throw.

## Diagnostic message

Each rule names the API and the member:

```text
Setup should be used only for overridable members, but '{0}' is not overridable
SetupSequence should be used only for overridable members, but '{0}' is not overridable
Verify should be used only for overridable members, but '{0}' is not overridable
```

For example, the build reports:

```text
error Moq1200: Setup should be used only for overridable members, but 'PriceService.GetPrice(string)' is not overridable
```

Moq1200 and Moq1207 show the full member signature. Moq1210 shows the bare member name, such as `'GetPrice'`.

## Why Moq needs overridable members

Moq builds a proxy type at run time with Castle DynamicProxy. For a class, the proxy is a subclass.
For an interface, the proxy implements the interface. Moq intercepts a call by overriding the member.

A class member must be `virtual` or `abstract`.
Interface members work unless they are `static` or sealed default interface members.

Moq cannot intercept these:

- Non-virtual methods and properties
- Static members
- Members marked `sealed override`
- Fields
- Sealed default interface members
- Extension methods

## How to fix

This example triggers the rule. `GetPrice` is not `virtual`.

```csharp
public class PriceService
{
    public decimal GetPrice(string sku) => 10m;
}

var mock = new Mock<PriceService>();
mock.Setup(x => x.GetPrice("A1")).Returns(5m); // Moq1200
mock.Verify(x => x.GetPrice("A1"));            // Moq1210
```

Pick one of three fixes.

### Extract an interface

Prefer this fix. Mock the interface instead of the class.

```csharp
public interface IPriceService
{
    decimal GetPrice(string sku);
}

public class PriceService : IPriceService
{
    public decimal GetPrice(string sku) => 10m;
}

var mock = new Mock<IPriceService>();
mock.Setup(x => x.GetPrice("A1")).Returns(5m);
```

Change the class under test to take `IPriceService` instead of `PriceService`.

### Make the member virtual

Use this fix when you own the class and cannot add an interface.

```csharp
public class PriceService
{
    public virtual decimal GetPrice(string sku) => 10m;
}

var mock = new Mock<PriceService>();
mock.Setup(x => x.GetPrice("A1")).Returns(5m);
```

Moq1200 has no code fix. The [Moq1210](Moq1210.md) code fix adds `virtual` for `Verify` calls.

### Wrap a sealed, static, or third-party type

You cannot add `virtual` to a type you do not own, and a static member can never be `virtual`.
Put the call behind your own interface and mock that interface.

```csharp
public interface IClock
{
    DateTimeOffset UtcNow { get; }
}

public sealed class SystemClock : IClock
{
    public DateTimeOffset UtcNow => DateTimeOffset.UtcNow;
}

var clock = new Mock<IClock>();
clock.Setup(x => x.UtcNow).Returns(new DateTimeOffset(2026, 1, 1, 0, 0, 0, TimeSpan.Zero));
```

Production code uses `SystemClock`. Tests use the mock.

For time, .NET 8 and later include `TimeProvider`. If your code takes a `TimeProvider`, the
`Microsoft.Extensions.TimeProvider.Testing` package adds `FakeTimeProvider`, so you need no wrapper and no mock.

## Same error from SetupSequence and Verify

- `mock.SetupSequence(x => x.GetPrice("A1"))` on a non-virtual member triggers [Moq1207](Moq1207.md).
- `mock.Verify(x => x.GetPrice("A1"))` on a non-virtual member triggers [Moq1210](Moq1210.md).

The same three fixes apply to both. After the fix, `Verify` passes once the code under test calls the member.

## Sealed default interface members

An interface member is normally overridable. A `sealed` default interface member is not, and Moq 4.18.4 cannot
intercept it. Moq1200 reports it.

```csharp
public interface IService
{
    sealed void Save() { }
}

new Mock<IService>().Setup(x => x.Save()); // Moq1200
```

## Suppress a warning

Suppressing Moq1200 does not stop the runtime exception. It hides the build error, and the test still throws.

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1200
mock.Setup(x => x.GetPrice("A1")).Returns(5m); // Moq1200: Setup should be used only for overridable members
#pragma warning restore Moq1200
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1200.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).

## FAQ

### What does "Invalid setup on a non-virtual member" mean in Moq?

Moq can only replace members it can override. Those are interface members and `virtual` or `abstract` class members.
Moq1200 catches the setup at build time.

### What does "Non-overridable members may not be used in setup / verification expressions" mean?

It is the same error with newer wording. Moq 4.11.0, 4.18.4, and 4.20.72 use this text.

### How do I mock a non-virtual method with Moq?

Extract an interface, make the method `virtual`, or wrap the type behind your own interface.
Moq cannot intercept a non-virtual method.

### Can Moq mock static or extension methods?

No. Wrap the call behind an interface and mock the interface.
For `ILogger` extension methods such as `LogInformation`, see [Moq1004](Moq1004.md).

### Why does Verify throw the same error?

`Verify` uses the same interception as `Setup`. [Moq1210](Moq1210.md) reports it and offers a code fix that adds
`virtual`.

### Does suppressing Moq1200 fix the error?

No. Suppression hides the build error. The test still throws at run time.
