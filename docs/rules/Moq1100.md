# Moq1100: Callback signature must match the signature of the mocked method

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | True    |

---

The parameters of a `Callback` or `Returns` lambda must match the parameters of the method in `Setup`. Match the
number, the order, and the types. A lambda with no parameters is always valid.

If they do not match, Moq throws `System.ArgumentException` when the test runs. Moq1100 reports the mismatch at build
time.

For how to use `Callback`, with samples for `out`, `ref`, and async methods, see
[How to use Callback in Moq](../moq-callback.md).

## Runtime error this rule prevents

The messages below are from Moq 4.18.4 and 4.20.72. Moq throws the first two from the `Callback` or `Returns` call
itself, so the test fails on the setup line.

A `Callback` with the wrong number, order, or type of parameters:

```text
Invalid callback. Setup on method with parameters ({0}) cannot invoke callback with parameters ({1}).
```

For example:

```text
System.ArgumentException: Invalid callback. Setup on method with parameters (int, string, DateTime) cannot invoke callback with parameters (string, int).
```

A `Returns` lambda with the wrong number of parameters:

```text
Invalid callback. Setup on method with {0} parameter(s) cannot invoke callback with different number of parameters ({1}).
```

For example:

```text
System.ArgumentException: Invalid callback. Setup on method with 3 parameter(s) cannot invoke callback with different number of parameters (1).
```

A `Returns` lambda with the right number of parameters and the wrong types passes setup. It throws
`System.ArgumentException` when the mocked method is called:

```text
Object of type 'System.Int32' cannot be converted to type 'System.String'.
```

## Diagnostic message

```text
Callback signature for '{0}' must match the signature of the mocked method
```

`{0}` is the name of the mocked method. The build output for a setup on `Place` starts with:

```text
warning Moq1100: Callback signature for 'Place' must match the signature of the mocked method
```

The message says "Callback" for a `Returns` lambda as well.

## Examples of flagged code

The examples use this interface and delegate.

```csharp
public delegate void WrongPlaceCallback(string sku, int id, DateTime at);

public interface IOrderService
{
    int Place(int id, string sku, DateTime at);
    bool TryGet(int id, out string sku);
}
```

Each setup below raises Moq1100.

```csharp
var mock = new Mock<IOrderService>();

// Wrong number of parameters
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback((string sku, int id) => { })
    .Returns(1);

// Wrong order
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback((string sku, int id, DateTime at) => { })
    .Returns(1);

// Wrong type arguments on Callback<T>
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback<string, int, DateTime>((sku, id, at) => { })
    .Returns(1);

// Returns lambda with the wrong number of parameters
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Returns((int id) => id);

// Returns lambda with the wrong order
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Returns((string sku, int id, DateTime at) => 1);

// Delegate constructor whose delegate type does not match the method
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback(new WrongPlaceCallback((string sku, int id, DateTime at) => { }))
    .Returns(1);

// Missing out modifier
mock.Setup(x => x.TryGet(It.IsAny<int>(), out It.Ref<string>.IsAny))
    .Callback((int id, string sku) => { })
    .Returns(true);
```

Moq.Analyzers 0.4.2 reports all of these except the `Callback<T>` form. It also misses a mismatched callback on a
method that returns `void`. Builds of the analyzer from `main` report both.

## Examples of code that is not flagged

```csharp
public delegate void PlaceCallback(int id, string sku, DateTime at);
public delegate void TryGetCallback(int id, out string sku);
```

```csharp
var mock = new Mock<IOrderService>();

// No parameters
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback(() => { })
    .Returns(1);

// Matching parameters, on Callback and on Returns
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback((int id, string sku, DateTime at) => { })
    .Returns((int id, string sku, DateTime at) => id);

// Matching type arguments
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback<int, string, DateTime>((id, sku, at) => { })
    .Returns(1);

// Matching delegate constructor
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback(new PlaceCallback((int id, string sku, DateTime at) => { }))
    .Returns(1);

// Callbacks before and after Returns
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback(() => Console.WriteLine("Before"))
    .Returns(1)
    .Callback(() => Console.WriteLine("After"));

// Out parameter through a custom delegate
mock.Setup(x => x.TryGet(It.IsAny<int>(), out It.Ref<string>.IsAny))
    .Callback(new TryGetCallback((int id, out string sku) => sku = "A1"))
    .Returns(true);
```

The analyzer reads each parameter's modifier from the resolved symbol. Parameters marked `scoped ref` or
`ref readonly` match and raise no warning.

## Mismatches this rule does not report

Moq rejects the callbacks below at run time and Moq1100 stays silent. They are tracked in
[#1434](https://github.com/rjmurillo/moq.analyzers/issues/1434).

The first kind is a callback parameter of a different type that C# can convert. Examples: `long` or `short` for an
`int` parameter, or `string` for an `object` parameter. A base type works, such as `object` for an `int` parameter.
The second kind is a delegate with a return value passed to `Callback`.

```csharp
public delegate bool TryGetReturns(int id, out string sku);
```

```csharp
// long for an int parameter
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback((long id, string sku, DateTime at) => { })
    .Returns(1);

// Callback given a delegate that returns a value
mock.Setup(x => x.TryGet(It.IsAny<int>(), out It.Ref<string>.IsAny))
    .Callback(new TryGetReturns((int id, out string sku) => { sku = "A1"; return true; }))
    .Returns(true);
```

The second one throws this message. `Callback` accepts `void` delegates only. Pass a delegate with a return value to
`Returns`.

```text
Invalid callback. This overload of the "Callback" method only accepts "void" (C#) or "Sub" (VB.NET) delegates with parameter types matching those of the set up method.
```

## How to fix

Change the lambda parameters to match the method in `Setup`.

```csharp
var mock = new Mock<IOrderService>();

mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback((int id, string sku, DateTime at) => { })
    .Returns(1);
```

A code fix rewrites the parameter list of a lambda passed to `Callback` or `Returns`. It keeps your parameter names
by position and takes the types and modifiers from the method, so check the names afterward.

```csharp
.Callback((string sku, int id) => { })              // before
.Callback((int sku, string id, DateTime at) => { }) // after the code fix
```

The code fix has three limits:

- It does not change the type arguments of `Callback<T>`. Fix those by hand.
- It adds a missing `out` modifier and no assignment. The result does not compile (CS0177) until you assign the
  value. `Action` cannot declare `out`, so use a custom delegate. See
  [Out and ref parameters](../moq-callback.md#out-and-ref-parameters).
- It does not change a lambda inside a delegate constructor. Change the delegate type by hand.

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
var mock = new Mock<IOrderService>();

#pragma warning disable Moq1100
mock.Setup(x => x.Place(It.IsAny<int>(), It.IsAny<string>(), It.IsAny<DateTime>()))
    .Callback((string sku, int id) => { })
    .Returns(1);
#pragma warning restore Moq1100
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1100.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
