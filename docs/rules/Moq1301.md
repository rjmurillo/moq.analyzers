# Moq1301: Mock.Get() should not take literals

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

`Mock.Get()` retrieves the `Mock` instance associated with a mocked object. Don't call `Mock.Get()` with a literal value,
because a literal can't have a mock instance associated with it.

The rule reports an argument that is a literal, a `default` or `default(T)` expression, or a cast of one of these. The
warning points at the argument.

## Diagnostic message

The message quotes the argument. For example, the build reports:

```text
warning Moq1301: Mock.Get() should not take literal 'literal string'
```

## Runtime error this rule prevents

Without the analyzer, the code compiles. `Mock.Get()` throws `System.ArgumentException` on the line that calls it,
because the argument is not an object that Moq created.

Checked at Moq 4.8.2, 4.18.4, and 4.20.72 on .NET 10:

```text
Object instance was not created by Moq. (Parameter 'mocked')
```

## Examples of flagged code

```csharp
public interface IMyInterface
{
    int Calculate(int a, int b);
}

var fromString = Mock.Get("literal string"); // Moq1301: Mock.Get() should not take literals
var fromNull = Mock.Get<IMyInterface>(null); // Moq1301: Mock.Get() should not take literals
var fromDefault = Mock.Get<IMyInterface>(default(IMyInterface)); // Moq1301: Mock.Get() should not take literals
```

`Mock.Get<T>(T mocked)` requires `T` to be a reference type. `Mock.Get(42)` does not compile (CS0452), because the
compiler infers `T` as `int`. `Mock.Get(null)` does not compile either, because the compiler cannot infer `T`
(CS0411). Name the type argument, as in `Mock.Get<IMyInterface>(null)`, and the rule reports it.

## How to fix

Pass a mocked object to `Mock.Get()` instead of a literal:

```csharp
public interface IMyInterface
{
    int Calculate(int a, int b);
}

var mockObject = new Mock<IMyInterface>().Object;
var mock = Mock.Get(mockObject); // Correct usage
```

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1301
var mock = Mock.Get("literal string"); // Moq1301: Mock.Get() should not take literals
#pragma warning restore Moq1301
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1301.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
