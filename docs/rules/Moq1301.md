# Moq1301: Mock.Get() should not take literals

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

`Mock.Get()` retrieves the `Mock` instance associated with a mocked object. Don't call `Mock.Get()` with a literal value,
because a literal can't have a mock instance associated with it.

## Examples of flagged code

```csharp
var mock = Mock.Get("literal string"); // Moq1301: Mock.Get() should not take literals
var mock = Mock.Get(42); // Moq1301: Mock.Get() should not take literals
var mock = Mock.Get(null); // Moq1301: Mock.Get() should not take literals
```

## How to fix

Pass a mocked object to `Mock.Get()` instead of a literal:

```csharp
var mockObject = new Mock<IMyInterface>().Object;
var mock = Mock.Get(mockObject); // Correct usage
```

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1301
var mock = Mock.Get("literal string"); // Moq1301: Mock.Get() should not take literals
#pragma warning restore Moq1301
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1301.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
