# Moq1002: Parameters provided into mock do not match any existing constructors

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

Moq passes the arguments you give `Mock<T>` to a constructor of the mocked class. If no constructor takes those
arguments, Moq throws when you read `mock.Object`.

To fix the violation, change the arguments so they match a constructor of the mocked class.

For more ways to pass constructor arguments, see
[Mocking a class with constructor parameters in Moq](../moq-constructor-arguments.md).

## Diagnostic message

The message names the mocked type and lists the arguments. For example, the build reports:

```text
warning Moq1002: Could not find a matching constructor for type 'MyClass' with arguments (3)
```

When you pass no arguments and the class has no parameterless constructor, the list is empty:

```text
warning Moq1002: Could not find a matching constructor for type 'MyClass' with arguments ()
```

## Runtime error this rule prevents

Without the analyzer, the code compiles. Moq 4.18.4 and 4.20.72 throw `System.ArgumentException` when you read
`mock.Object`. The message lists the type of each argument you passed.

```text
Can not instantiate proxy of class: MyClass.
Could not find a constructor that would match given arguments:
System.Int32
 (Parameter 'constructorArguments')
```

With no arguments, the message is:

```text
Can not instantiate proxy of class: MyClass.
Could not find a parameterless constructor. (Parameter 'constructorArguments')
```

`Mock.Of<T>()` throws the same exception on the call itself.

Castle.Core, the library Moq uses to build the mock, writes this text. Moq 4.8.2 and 4.17.1 use Castle.Core 4. They
print the same lines without the `(Parameter ...)` part. They throw
`Castle.DynamicProxy.InvalidProxyConstructorArgumentsException`, which derives from `ArgumentException`.

## What the rule checks

- `new Mock<T>(...)`, target-typed `new(...)`, `MockRepository.Create<T>(...)`, and `Mock.Of<T>()`.
- The number of arguments, and whether each argument converts to the parameter type.
- A `MockBehavior` argument is not a constructor argument. The rule skips it.
- `private` constructors do not count as a match. Moq cannot call them.
- Any constructor argument on a delegate mock, such as `new Mock<Action>(1)`.

Moq.Analyzers 0.4.2 does not check the target-typed `new(...)` form. The check is on main and is not in a released version yet.

## Examples of flagged code

```csharp
public class MyClass
{
    public MyClass(string s) { }
}

var mock = new Mock<MyClass>(3); // Moq1002
Mock<MyClass> targetTypedMock = new(3); // Moq1002
var noArguments = new Mock<MyClass>(); // Moq1002
var behaviorOnly = new Mock<MyClass>(MockBehavior.Strict); // Moq1002
MyClass instance = Mock.Of<MyClass>(); // Moq1002

var repository = new MockRepository(MockBehavior.Strict);
Mock<MyClass> fromRepository = repository.Create<MyClass>(3); // Moq1002
```

## How to fix

```csharp
public class MyClass
{
    public MyClass(string s) { }
}

var mock = new Mock<MyClass>("three");
Mock<MyClass> targetTypedMock = new("three");
var strict = new Mock<MyClass>(MockBehavior.Strict, "three");

var repository = new MockRepository(MockBehavior.Strict);
Mock<MyClass> fromRepository = repository.Create<MyClass>("three");
```

## Limits of this rule

Checked with Moq 4.20.72. Each limit has a tracking issue, and the behavior may change.

- The rule does not check the lambda form, `new Mock<MyClass>(() => new MyClass("three"))`. The compiler checks the
  constructor call inside the lambda. The lambda form needs Moq 4.13.0 or later. On Moq 4.12.0 with C# 10 or later,
  the line compiles, the rule stays silent, and `mock.Object` throws. See [issue 1446](https://github.com/rjmurillo/moq.analyzers/issues/1446).
- The rule does not report a missing optional argument. Moq does not fill in default values, so the mock fails at
  run time. Pass every argument. See [issue 1443](https://github.com/rjmurillo/moq.analyzers/issues/1443).
- The rule does not report an `internal` constructor. Moq can call one only when the assembly grants
  `InternalsVisibleTo("DynamicProxyGenAssembly2")`. See [Moq1003](Moq1003.md) for the attribute, and
  [issue 1445](https://github.com/rjmurillo/moq.analyzers/issues/1445).
- The rule reports an array passed to a `params` parameter. For a constructor
  `BatchService(string name, params int[] sizes)`, it reports `new Mock<BatchService>("nightly", new[] { 10, 20 })`.
  Moq accepts that call. Pass the values one by one, or suppress the warning. See [issue 1444](https://github.com/rjmurillo/moq.analyzers/issues/1444).

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1002
var mock = new Mock<MyClass>(3);
#pragma warning restore Moq1002
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1002.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
