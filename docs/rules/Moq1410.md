# Moq1410: Explicitly set the Strict mocking behavior

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Info    |
| CodeFix  | True    |

---

Moq1410 reports every mock that is not created with `MockBehavior.Strict`. A Strict mock throws a `MockException` for
any call without a setup. A Loose mock, the Moq default, returns a default value and never throws.

Use this rule when your team requires Strict mocks. [Moq1400](Moq1400.md) is the lighter rule: it accepts `Loose` or
`Strict` as long as you choose one. For what each behavior does, see
[MockBehavior.Strict vs MockBehavior.Loose](Moq1400.md#mockbehaviorstrict-vs-mockbehaviorloose).

## Diagnostic message

```text
Explicitly set the Strict mocking behavior for '{0}'
```

The default severity is Info, so `dotnet build` does not print the message by default. With the severity raised to `warning`,
the build reports this for `new Mock<ISample>()`:

```text
warning Moq1410: Explicitly set the Strict mocking behavior for 'ISample'
```

## What this rule flags

Moq1410 checks `new Mock<T>(...)`, `Mock.Of<T>(...)`, and `new MockRepository(...)`. It reports a missing behavior,
`MockBehavior.Default`, and an explicit `MockBehavior.Loose`.

```csharp
var mock = new Mock<ISample>();                       // Moq1410
var mock2 = Mock.Of<ISample>();                       // Moq1410
var mock3 = new Mock<ISample>(MockBehavior.Default);  // Moq1410
var mock4 = Mock.Of<ISample>(MockBehavior.Default);   // Moq1410
var repo = new MockRepository(MockBehavior.Default);  // Moq1410
var loose = new Mock<ISample>(MockBehavior.Loose);    // Moq1410
var looseRepo = new MockRepository(MockBehavior.Loose); // Moq1410

public interface ISample
{
    int Calculate();
}
```

Moq1410 reads the argument only. It does not follow a variable to its value, so it reports a behavior passed
through a local variable, even one that holds `MockBehavior.Strict`. A `const` that holds `MockBehavior.Strict` is
accepted.

```csharp
var behavior = MockBehavior.Strict;
var mock = new Mock<ISample>(behavior);     // Moq1410

const MockBehavior Strict = MockBehavior.Strict;
var mock2 = new Mock<ISample>(Strict);      // no diagnostic
```

Moq1410 does not report `repository.Create<T>()`. The mock takes the behavior of its `MockRepository`.

## How to fix

Pass `MockBehavior.Strict`. The code fix is **Set MockBehavior (Strict)**. Then add a setup for each call the test
makes.

```csharp
var mock = new Mock<ISample>(MockBehavior.Strict);
mock.Setup(x => x.Calculate()).Returns(42);
var mock2 = Mock.Of<ISample>(MockBehavior.Strict);
var repo = new MockRepository(MockBehavior.Strict);

public interface ISample
{
    int Calculate();
}
```

## Change the severity

Raise the severity to make the build report the rule:

```ini
[*.cs]
dotnet_diagnostic.Moq1410.severity = warning
```

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1410
var mock = new Mock<ISample>();
#pragma warning restore Moq1410
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1410.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
