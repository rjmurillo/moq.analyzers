# Moq1205: Event setup handler type should match event delegate type

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

## Cause

Handler type passed to `SetupAdd` or `SetupRemove` does not match the event delegate type.

## Rule description

When you set up an event on a mocked object using `SetupAdd` or `SetupRemove`, you are telling Moq how to behave when code subscribes to or unsubscribes from that event. A common way to do this is to specify the type of delegate that can be added or removed, often using `It.IsAny<T>()`.

This rule ensures that the delegate type you specify in your setup (e.g., `It.IsAny<Action<int>>`) is compatible with the actual delegate type of the event (e.g., `event Action<string>`).

**Why this is important:** The handler type in the setup must convert to the event's delegate type. For the common mismatches, such as `It.IsAny<Action<int>>()` on an `event Action<string>`, the C# compiler already rejects the code with error CS0029, so the build fails and you see CS0029, not Moq1205. The analyzer applies the same conversion test as the compiler. This repository's tests contain no pattern that compiles and still reports Moq1205, so treat CS0029 as the signal for this mistake.

## How to fix violations

Ensure that the handler type passed to `SetupAdd` or `SetupRemove` matches the event's delegate type.

## When to suppress warnings

It is not recommended to suppress warnings from this rule. An incorrect handler type is a defect in the test. If you have a scenario where suppression is necessary, use one of the methods described below.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to
your source file to disable and then re-enable the rule. Put the line that reports Moq1205 between them.

```csharp
#pragma warning disable Moq1205
// The SetupAdd or SetupRemove call that reports Moq1205 goes here.
#pragma warning restore Moq1205
```

The directives suppress Moq1205 only. They do not suppress compiler error CS0029, so a handler type that does not
convert to the event type still fails to build.

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1205.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).

## Example of a violation

```csharp
interface INotifier
{
    event Action<string> StringChanged;
}

class Test
{
    void TestMethod()
    {
        var mock = new Mock<INotifier>();
        
        // Wrong: passing Action<int> instead of Action<string>.
        // The compiler also reports CS0029 on this line.
        mock.SetupAdd(x => x.StringChanged += It.IsAny<Action<int>>());
    }
}
```

## Example of how to fix

```csharp
interface INotifier
{
    event Action<string> StringChanged;
}

class Test
{
    void TestMethod()
    {
        var mock = new Mock<INotifier>();
        
        // Correct: passing Action<string> as expected by the event
        mock.SetupAdd(x => x.StringChanged += It.IsAny<Action<string>>());
    }
}
```

## Supported event delegate types

- `Action` (no parameters)
- `Action<T>`, `Action<T1, T2>`, etc. (generic Action delegates)
- `EventHandler<T>` (standard .NET event handler pattern)
- Custom delegate types (analyzed via their signature)

## Compatibility

This rule only applies to Moq 4.18.4+ as `SetupAdd` and `SetupRemove` are not available in earlier versions.
