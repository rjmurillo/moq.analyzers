# Moq1205: Event setup handler type should match event delegate type

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

## Cause

The handler type passed to `SetupAdd` or `SetupRemove` does not match the event delegate type.

## Rule description

When you set up an event on a mocked object with `SetupAdd` or `SetupRemove`, you tell Moq how to behave when code
subscribes to or unsubscribes from that event. A common way to do this is to specify the type of delegate that can be
added or removed, often with `It.IsAny<T>()`.

This rule checks that the delegate type you specify in your setup (for example, `It.IsAny<Action<int>>`) is compatible
with the delegate type of the event (for example, `event Action<string>`).

**Why this is important:** If the types do not match, your test code still compiles. However, when the test runs and
code accesses the event, Moq throws an exception because it cannot handle the incorrect delegate type. The analyzer
reports the mismatch during development, so you do not have to debug an unexpected test failure.

## How to fix violations

Change the handler type you pass to `SetupAdd` or `SetupRemove` so it matches the event's delegate type.

## When to suppress warnings

We do not recommend suppressing warnings from this rule. Incorrect handler types cause exceptions at run time. If you
must suppress the rule, see [Suppress a warning](#suppress-a-warning).

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1205
mock.SetupAdd(x => x.StringChanged += It.IsAny<Action<int>>());
#pragma warning restore Moq1205
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1205.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).

## Example of a violation

```csharp
interface INotifier
{
    event Action<string> StringChanged;
}

class Test
{
    void TestMethod()
    {
        var mock = new Mock<INotifier>();
        
        // Wrong: passing Action<int> instead of Action<string>
        mock.SetupAdd(x => x.StringChanged += It.IsAny<Action<int>>());
    }
}
```

## Example of how to fix

```csharp
interface INotifier
{
    event Action<string> StringChanged;
}

class Test
{
    void TestMethod()
    {
        var mock = new Mock<INotifier>();
        
        // Correct: passing Action<string> as expected by the event
        mock.SetupAdd(x => x.StringChanged += It.IsAny<Action<string>>());
    }
}
```

## Supported event delegate types

- `Action` (no parameters)
- `Action<T>`, `Action<T1, T2>`, etc. (generic Action delegates)
- `EventHandler<T>` (standard .NET event handler pattern)
- Custom delegate types (the analyzer checks their signature)

## Compatibility

This rule applies only to Moq 4.18.4 and later, because `SetupAdd` and `SetupRemove` are not available in earlier
versions.
