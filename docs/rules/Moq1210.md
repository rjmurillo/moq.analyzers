# Moq1210: Verify should be used only for overridable members

| Item     | Value |
| -------- | ----- |
| Enabled  | True  |
| Severity | Error |
| CodeFix  | True  |

---

Moq creates a dynamic proxy type at runtime. For a class, the proxy inherits from the class and overrides its `virtual`
or `abstract` members. For an interface, the proxy implements the interface. These overrides let Moq intercept calls
and implement mocking behavior, including verification.

Because of this design, Moq can only intercept calls to members that are overridable:

- Members of an interface (which are implicitly virtual).
- `virtual` or `abstract` members of a non-sealed class.

Sealed default interface members are not overridable. Moq 4.18.4 throws
`System.NotSupportedException` when they appear in `Verify` expressions, so this
rule reports them.

The .NET CLR does not let a subclass override a non-virtual member, so Moq's proxy cannot intercept calls to it. If you
`Verify` a non-virtual member, Moq throws a `System.NotSupportedException` at runtime.

The analyzer finds `Verify` calls on non-overridable members at compile time, so you can fix them before the test fails
at runtime.

## Same error, different API

`Verify` fails the same way `Setup` does. Moq 4.7.145 and 4.10.1 throw this text:

```text
Invalid verify on a non-virtual (overridable in VB) member: {0}
```

Moq 4.18.4 and 4.20.72 throw this text:

```text
Unsupported expression: {0}
Non-overridable members (here: {0}) may not be used in setup / verification expressions.
```

For the version notes, see [Runtime error this rule prevents](Moq1200.md#runtime-error-this-rule-prevents) in Moq1200.

## How to fix

Use `Verify` only with virtual, abstract, or interface members:

- Prefer mocking an interface instead of a concrete class.
- If you mock a class you own, mark the member as `virtual`.
- For a type you do not own, wrap it behind your own interface.

[Moq1200](Moq1200.md#how-to-fix) shows each fix with code.

## Example

The analyzer flags the following code because `MyMethod` is not overridable:

```csharp
public class MyClass
{
    public int MyMethod()
    {
        return 1;
    }
}

var mock = new Mock<MyClass>();
mock.Verify(x => x.MyMethod());
```

To fix a class member, make the method `virtual`:

```csharp
public class MyClass
{
    public virtual int MyMethod()
    {
        return 1;
    }
}

var mock = new Mock<MyClass>();
mock.Verify(x => x.MyMethod());
```

The code fix appears only when `virtual` is legal. It does not appear for
static members, members of sealed classes, struct members, or interface members.

## Examples of valid code

```csharp
public class SampleClass
{
    public virtual int Property { get; set; }
    public virtual int VirtualMethod() => 0;
}

var mock = new Mock<SampleClass>();
mock.Verify(x => x.Property);
mock.Verify(x => x.VirtualMethod());
mock.VerifyGet(x => x.Property);
mock.VerifySet(x => x.Property = 42);
mock.VerifyNoOtherCalls(); // This method doesn't verify specific members, so it's always valid
```

## Suppress a warning

Suppressing Moq1210 does not stop the runtime exception. It only hides the build error.

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1210
mock.Verify(x => x.Property); // Moq1210: Verify should be used only for overridable members
#pragma warning restore Moq1210
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1210.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
