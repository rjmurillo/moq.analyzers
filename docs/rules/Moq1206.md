# Moq1206: Async method setups should use ReturnsAsync instead of Returns with async lambda

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

When you set up an async method, use `.ReturnsAsync()` instead of `.Returns()` with an async lambda. The async lambda
runs and returns the right value. `.ReturnsAsync()` does the same job in one call, without the `async` keyword.

## Examples of flagged code

```csharp
public class AsyncClient
{
    public virtual Task<string> GetAsync() => Task.FromResult(string.Empty);
    public virtual Task DoAsync() => Task.CompletedTask;
}

var mock = new Mock<AsyncClient>();

// These patterns are flagged:
mock.Setup(c => c.GetAsync()).Returns(async () => "value"); // Moq1206: Async method setups should use ReturnsAsync instead of Returns with async lambda
mock.Setup(c => c.DoAsync()).Returns(async () => { }); // Moq1206: Async method setups should use ReturnsAsync instead of Returns with async lambda
```

The build reports one warning per line:

```text
warning Moq1206: Async method 'GetAsync' setups should use ReturnsAsync instead of Returns with async lambda
warning Moq1206: Async method 'DoAsync' setups should use ReturnsAsync instead of Returns with async lambda
```

## How to fix

```csharp
public class AsyncClient
{
    public virtual Task<string> GetAsync() => Task.FromResult(string.Empty);
    public virtual Task DoAsync() => Task.CompletedTask;
}

var mock = new Mock<AsyncClient>();

// Task<T>: use ReturnsAsync.
mock.Setup(c => c.GetAsync()).ReturnsAsync("value");

// Task with no value: return a completed task. Moq has no ReturnsAsync() overload without arguments.
mock.Setup(c => c.DoAsync()).Returns(Task.CompletedTask);

// Or use synchronous lambdas that return tasks:
mock.Setup(c => c.GetAsync()).Returns(() => Task.FromResult("value"));
mock.Setup(c => c.DoAsync()).Returns(() => Task.CompletedTask);
```

For `ValueTask`, `null`, and methods with parameters, see
[How to set up async methods in Moq](../moq-returnsasync.md).

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1206
mock.Setup(c => c.GetAsync()).Returns(async () => "value"); // Moq1206: Async method setups should use ReturnsAsync instead of Returns with async lambda
#pragma warning restore Moq1206
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1206.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
