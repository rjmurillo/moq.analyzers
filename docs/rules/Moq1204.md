# Moq1204: Raises event arguments should match the event delegate signature

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

## Cause

Arguments passed to `Raises()` do not match the event delegate signature.

## Rule description

Use the `Raises` method to raise an event when code calls a mocked method. For example, you can configure a `Submit()`
method to raise a `Completed` event.

To identify the event, `Raises` takes a lambda expression like `x => x.Completed += null`. The `+= null` part is the standard Moq syntax for
targeting an event without providing a handler.

This rule checks that the arguments you pass to `Raises` are compatible with the signature of the event's delegate. For
example, if an event is declared as `event Action<string>`, you must call `Raises` with a `string` argument.

**Why this is important:** If the arguments do not match the event's delegate signature, your test code still compiles.
However, the test fails at run time when Moq tries to invoke the event with the mismatched arguments. The analyzer
reports the mismatch at compile time, before you run the test.

## How to fix violations

Change the arguments you pass to `Raises()` so they match the parameter types of the event delegate.

## When to suppress warnings

We do not recommend suppressing warnings from this rule. Incorrect event arguments cause exceptions at run time. If you
must suppress the rule, see [Suppress a warning](#suppress-a-warning).

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1204
mock.Setup(x => x.Submit()).Raises(x => x.Completed += null, 42);
#pragma warning restore Moq1204
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1204.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).

## Example of a violation

```csharp
interface INotifier
{
    void Submit();
    event Action<string> Completed;
}

class Test
{
    void TestMethod()
    {
        var mock = new Mock<INotifier>();
        
        // Wrong: passing int instead of string
        mock.Setup(x => x.Submit()).Raises(x => x.Completed += null, 42);
    }
}
```

## Example of how to fix

```csharp
interface INotifier
{
    void Submit();
    event Action<string> Completed;
}

class Test
{
    void TestMethod()
    {
        var mock = new Mock<INotifier>();
        
        // Correct: passing string as expected by Action<string>
        mock.Setup(x => x.Submit()).Raises(x => x.Completed += null, "success");
    }
}
```

## Supported event delegate types

- `Action` (no parameters)
- `Action<T>`, `Action<T1, T2>`, etc. (generic Action delegates)
- `EventHandler` (accepts `EventArgs` only, because Moq supplies the sender)
- `EventHandler<T>` where `T` derives from `EventArgs`
- Custom `(object sender, TArgs e)` delegates where `TArgs` derives from `EventArgs`
- Custom delegate types (the analyzer checks the signature of their `Invoke` method)

For `EventHandler`-shaped delegates, both forms are valid:

```csharp
mock.Setup(x => x.Submit()).Raises(x => x.Completed += null, EventArgs.Empty);
mock.Setup(x => x.Submit()).Raises(x => x.Completed += null, new object(), EventArgs.Empty);
```

In the first form, Moq supplies the sender. In the second form, you pass the
full delegate argument list.

## Compatibility

This rule applies to all supported Moq versions, because the `Raises` method has been available since early versions.
