# Moq1400: Explicitly choose a mocking behavior instead of relying on the default (Loose) behavior

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | True    |

---

Moq mocks are Loose by default: calls without a setup return default values and never throw. Strict mocks throw a
`MockException` for any call without a setup. Moq1400 asks you to pass one of them on purpose so the choice is visible
in the test.

## MockBehavior.Strict vs MockBehavior.Loose

`MockBehavior` has three names and two values. `MockBehavior.Default` equals `MockBehavior.Loose`.

The table shows what a mock from `new Mock<T>(...)` does when your code calls a member that has no setup.

| Call with no setup | `MockBehavior.Loose` | `MockBehavior.Strict` |
| --- | --- | --- |
| Method that returns `int` | Returns `0` | Throws `MockException` |
| Method that returns `string` or an interface | Returns `null` | Throws `MockException` |
| Method that returns `IEnumerable<int>` or `int[]` | Returns an empty sequence or array | Throws `MockException` |
| Method that returns `Task` or `Task<int>` | Returns a completed task. The `Task<int>` result is `0` | Throws `MockException` |
| `void` method | Does nothing | Throws `MockException` |
| Property get | Returns the default value | Throws `MockException` |
| Property set | Does nothing. A later get still returns the default value | Throws `MockException` |

`Verify` works the same way for both behaviors. `mock.Verify(x => x.Save(), Times.Once())` throws a `MockException`
when `Save` was never called, on a Loose mock and on a Strict mock.

`Mock.Of<T>()` differs in one row. It stubs properties, so a Loose `Mock.Of<T>()` mock returns the value you set.

Every cell comes from a run on Moq 4.18.4, 4.20.72, and 4.21.0.

### The Strict exception

This code calls a Strict mock that has no setup:

```csharp
var strict = new Mock<ISample>(MockBehavior.Strict);
strict.Object.Calculate(); // throws MockException

var loose = new Mock<ISample>(MockBehavior.Loose);
int value = loose.Object.Calculate(); // returns 0

public interface ISample
{
    int Calculate();
}
```

Moq 4.20.72 prints:

```text
Moq.MockException: ISample.Calculate() invocation failed with mock behavior Strict.
All invocations on the mock must have a corresponding setup.
```

The first line names the member your code called. Moq 4.13.1, 4.18.4, and 4.21.0 print the same text.

## Diagnostic message

```text
Explicitly choose a mocking behavior for {0} instead of relying on the default (Loose) behavior
```

For `new Mock<ISample>()`, the build reports:

```text
warning Moq1400: Explicitly choose a mocking behavior for ISample instead of relying on the default (Loose) behavior
```

## What this rule flags

Moq1400 checks three ways to create a mock: `new Mock<T>(...)`, `Mock.Of<T>(...)`, and `new MockRepository(...)`.
It reports a call that passes no behavior and a call that passes `MockBehavior.Default`.

```csharp
var mock = new Mock<ISample>();                          // Moq1400
Mock<ISample> mock2 = new();                             // Moq1400
var mock3 = Mock.Of<ISample>();                          // Moq1400
var mock4 = Mock.Of<ISample>(x => x.Calculate() == 1);   // Moq1400
var mock5 = new Mock<ISample>(MockBehavior.Default);     // Moq1400
var mock6 = Mock.Of<ISample>(MockBehavior.Default);      // Moq1400
var repo = new MockRepository(MockBehavior.Default);     // Moq1400

public interface ISample
{
    int Calculate();
}
```

Moq1400 does not report these:

- `MockBehavior.Loose` or `MockBehavior.Strict` passed as the argument.
- `repository.Create<T>()`. The mock takes the behavior of its `MockRepository`.
- A behavior passed through a variable or a constant. Moq1400 reads the argument only, so
  `var b = MockBehavior.Default; new Mock<ISample>(b);` gets no warning.

`Mock.Of<T>(MockBehavior)` needs a newer Moq. It compiles on Moq 4.13.1 and fails on Moq 4.10.1 with CS1503.

## How to fix

Pass `MockBehavior.Loose` or `MockBehavior.Strict`. The code fix offers both: **Set MockBehavior (Loose)** and
**Set MockBehavior (Strict)**.

Choose Strict, then add the setups the test needs:

```csharp
var mock = new Mock<ISample>(MockBehavior.Strict);
mock.Setup(x => x.Calculate()).Returns(42);
var mock2 = Mock.Of<ISample>(MockBehavior.Strict);
var repo = new MockRepository(MockBehavior.Strict);

public interface ISample
{
    int Calculate();
}
```

Or choose Loose and keep the current behavior:

```csharp
var mock = new Mock<ISample>(MockBehavior.Loose);
var mock2 = Mock.Of<ISample>(MockBehavior.Loose);
var repo = new MockRepository(MockBehavior.Loose);
```

## Choosing between them

This section is guidance. Moq1400 accepts either behavior.

- Strict fails the test on a call you did not plan for. You write a setup for every call, so tests get longer.
- Loose keeps tests short. A missing setup returns a default value, so call `Verify` for the interactions you care about.
- Pick one default for the team and state it in every test. Mixed, unstated behaviors are what Moq1400 removes.

## Moq1410: require Strict

[Moq1410](Moq1410.md) is the stricter rule. It reports every mock that is not `MockBehavior.Strict`, including an
explicit `MockBehavior.Loose`. Its default severity is Info, so `dotnet build` does not print it by default.

Turn it off if your team accepts Loose mocks:

```ini
[*.cs]
dotnet_diagnostic.Moq1410.severity = none
```

Raise it if your team requires Strict mocks:

```ini
[*.cs]
dotnet_diagnostic.Moq1410.severity = warning
```

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1400
var mock = new Mock<ISample>();
#pragma warning restore Moq1400
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1400.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).

## FAQ

### What is the default MockBehavior in Moq?

Loose. `MockBehavior.Default` equals `MockBehavior.Loose`.

### What is the difference between Strict and Loose mocks?

A Loose mock returns default values for calls without a setup. A Strict mock throws a `MockException` for them.

### What does "invocation failed with mock behavior Strict" mean?

Your code called a member of a Strict mock that has no matching setup. Add the setup or use a Loose mock.

### Should I use Strict or Loose?

It is a team choice. Moq1400 asks only that you choose explicitly. [Moq1410](Moq1410.md) enforces Strict and is
Info by default.

### Does Moq1400 have a code fix?

Yes. The fix offers "Set MockBehavior (Loose)" and "Set MockBehavior (Strict)".

### Why does `new Mock<T>(MockBehavior.Default)` still warn?

`Default` means Loose without saying so. Moq1400 treats it like a missing argument.
