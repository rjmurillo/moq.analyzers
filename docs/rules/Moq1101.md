# Moq1101: SetupGet/SetupSet/SetupProperty should be used for properties, not for methods

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

`.SetupGet()`, `.SetupSet()`, and `.SetupProperty()` mock properties, not methods. To mock a method, use `.Setup()`
instead.

To choose between these methods for a property, see [Mocking properties in Moq](../moq-property-setup.md).

## Diagnostic message

```text
SetupGet/SetupSet/SetupProperty should be used for properties, not for methods like '{0}'
```

The analyzer replaces `{0}` with the method name. For example, the build reports:

```text
warning Moq1101: SetupGet/SetupSet/SetupProperty should be used for properties, not for methods like 'Method'
```

## Examples of flagged code

The samples on this page use this interface.

```csharp
public interface IMyInterface
{
    string Name { get; set; }
    string Method();
}
```

```csharp
var mock = new Mock<IMyInterface>(MockBehavior.Strict);

mock.SetupGet(x => x.Method());      // Moq1101
mock.SetupSet(x => x.Method());      // Moq1101
mock.SetupProperty(x => x.Method()); // Moq1101
```

## How to fix

Use `Setup` for the method, and give it a return value. Keep the property methods for properties.

```csharp
var mock = new Mock<IMyInterface>(MockBehavior.Strict);

mock.Setup(x => x.Method()).Returns("value");
mock.SetupGet(x => x.Name).Returns("name");
```

`Setup` with no `Returns` on a method that returns a value triggers [Moq1203](Moq1203.md).

## Which property method to use

| You want to | Use |
| ----------- | --- |
| Return a fixed value from a property getter | `SetupGet(x => x.Name).Returns("name")` |
| Make a property remember assigned values | `SetupProperty(x => x.Name, "name")` |
| Allow or react to an assignment | `SetupSet(x => x.Name = "name")` |
| Set up a method | `Setup(x => x.Method()).Returns("value")` |

[Mocking properties in Moq](../moq-property-setup.md) covers each one, plus read-only properties and indexers.

## Runtime error this rule prevents

Without the analyzer, the flagged samples compile and the test fails when the setup line runs. The text below was
checked at Moq 4.18.4 and 4.20.72.

`SetupGet` and `SetupProperty` on a method throw `ArgumentException`:

```text
Expression is not a property access: x => x.Method()
```

`SetupSet` on a method throws `ArgumentException` with different text. The three dots are part of Moq's message.

```text
Unsupported expression: x => x.Method()...
The return type of the last member shown above is not mockable.
```

## What this rule does not report

- `SetupAllProperties()`. It takes no expression.
- `VerifyGet` or `VerifySet` on a method. Both throw `ArgumentException` at run time.
- `SetupProperty` on a property with no setter, or on an indexer. Both throw `ArgumentException` at run time. See
  [Read-only properties and properties without a setter](../moq-property-setup.md#read-only-properties-and-properties-without-a-setter).
- `Setup` on a property. That call is valid.

Moq.Analyzers 0.4.2 also misses two forms that the analyzer on `main` reports: the generic call
`SetupSet<string>(x => x.Method())`, and `SetupProperty` with named arguments in a different order.

## Suppress a warning

Suppressing Moq1101 does not stop the runtime exception. It hides the build warning, and the test still throws.

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1101
mock.SetupGet(x => x.Method()); // Moq1101
#pragma warning restore Moq1101
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1101.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
