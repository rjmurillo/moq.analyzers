# Moq1001: Mocked interfaces cannot have constructor parameters

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

An interface has no constructor, so an interface mock cannot take constructor arguments. Moq throws when you create
the mock.

To fix the violation, remove the constructor arguments. A `MockBehavior` is not a constructor argument, so you can
keep it.

To pass constructor arguments to a class mock, see
[Mocking a class with constructor parameters in Moq](../moq-constructor-arguments.md).

## Diagnostic message

The message names the interface and lists the arguments. For example, the build reports:

```text
warning Moq1001: Mocked interface 'IMyService' cannot have constructor parameters ("123")
```

## Runtime error this rule prevents

Without the analyzer, the code compiles. Moq throws `System.ArgumentException` on the line that creates the mock.

Checked at Moq 4.8.2, 4.18.4, and 4.20.72:

```text
Constructor arguments cannot be passed for interface mocks.
```

## Examples of flagged code

```csharp
public interface IMyService
{
    void Do(string s);
}

var mock = new Mock<IMyService>("123"); // Moq1001
Mock<IMyService> targetTypedMock = new("123"); // Moq1001

var repository = new MockRepository(MockBehavior.Strict);
Mock<IMyService> fromRepository = repository.Create<IMyService>("123"); // Moq1001
```

Moq.Analyzers 0.4.2 does not report the target-typed `new("123")` form. That check ships in the next release.

## How to fix

```csharp
public interface IMyService
{
    void Do(string s);
}

var mock = new Mock<IMyService>();
var strict = new Mock<IMyService>(MockBehavior.Strict);
Mock<IMyService> targetTypedMock = new();

var repository = new MockRepository(MockBehavior.Strict);
Mock<IMyService> fromRepository = repository.Create<IMyService>();
```

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1001
var mock = new Mock<IMyService>("123");
#pragma warning restore Moq1001
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1001.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
