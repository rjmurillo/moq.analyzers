# Moq1004: ILogger should not be mocked

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

Do not mock `ILogger` or `ILogger<T>` with Moq. Use `NullLogger` when the test ignores logging, and `FakeLogger`
when the test checks what was logged.

Moq1004 is not in Moq.Analyzers 0.4.2. It ships in the next release.

The samples on this page use xUnit and this class:

```csharp
using Microsoft.Extensions.Logging;

public class OrderService
{
    private readonly ILogger<OrderService> _logger;

    public OrderService(ILogger<OrderService> logger) => _logger = logger;

    public void PlaceOrder(int orderId) => _logger.LogInformation("Order {OrderId} placed", orderId);
}
```

## Diagnostic message

The rule reports one of two messages. You get the first for `ILogger` and the second for `ILogger<T>`.

```text
ILogger should not be mocked; use NullLogger.Instance or FakeLogger from Microsoft.Extensions.Diagnostics.Testing instead
ILogger should not be mocked; use NullLogger<T>.Instance or FakeLogger from Microsoft.Extensions.Diagnostics.Testing instead
```

`Microsoft.Extensions.Diagnostics.Testing` in the message is the NuGet package name. The `FakeLogger` type lives in the
`Microsoft.Extensions.Logging.Testing` namespace.

## What this rule flags

The rule flags three ways to create a mock of `ILogger` or `ILogger<T>`: `new Mock<T>()`, `Mock.Of<T>()`, and
`MockRepository.Create<T>()`. Any type argument counts, so `ILogger<OrderService>` and `ILogger<MyService>` are both
flagged.

```csharp
using Microsoft.Extensions.Logging;

var mock = new Mock<ILogger>(); // Moq1004
var mock2 = new Mock<ILogger<MyService>>(); // Moq1004
var logger = Mock.Of<ILogger>(); // Moq1004
var logger2 = Mock.Of<ILogger<MyService>>(); // Moq1004

var repository = new MockRepository(MockBehavior.Strict);
var mock3 = repository.Create<ILogger>(); // Moq1004
var mock4 = repository.Create<ILogger<MyService>>(); // Moq1004
```

The rule is a warning. Moq can still create the mock, and your tests still run.

## Why mocking ILogger is fragile

A mocked logger ties your test to the internals of the logging library. `LogInformation`, `LogWarning`, `LogError`,
and the other helpers are extension methods, and Moq cannot verify an extension method. This call compiles, then
throws `NotSupportedException` at run time. [Moq1210](Moq1210.md) reports it at build time.

```csharp
logger.Verify(x => x.LogInformation("Order {OrderId} placed", 42)); // throws NotSupportedException
```

The exception message ends with this line:

```text
Extension methods (here: LoggerExtensions.LogInformation) may not be used in setup / verification expressions.
```

To verify a log call, you must match the one interface method that every helper calls:

```csharp
void Log<TState>(
    LogLevel logLevel,
    EventId eventId,
    TState state,
    Exception? exception,
    Func<TState, Exception?, string> formatter);
```

`TState` is generic, so the test needs `It.IsAnyType` matchers. The result is this:

```csharp
var logger = new Mock<ILogger<OrderService>>(); // Moq1004
var service = new OrderService(logger.Object);

service.PlaceOrder(42);

logger.Verify(
    x => x.Log(
        LogLevel.Information,
        It.IsAny<EventId>(),
        It.Is<It.IsAnyType>((v, t) => v.ToString()!.Contains("Order 42 placed")),
        It.IsAny<Exception?>(),
        It.IsAny<Func<It.IsAnyType, Exception?, string>>()),
    Times.Once);
```

The test asserts one fact: the service logged "Order 42 placed" at `Information` level. It takes five arguments,
four of them matchers, to say so, and the message check depends on what `ToString()` returns for the state object.

## Tests that ignore logging: NullLogger

Pass `NullLogger<T>.Instance` when the test does not care about logs. It discards every entry.

```csharp
using Microsoft.Extensions.Logging.Abstractions;

var service = new OrderService(NullLogger<OrderService>.Instance);
```

Use `NullLogger.Instance` for the non-generic `ILogger`.

```csharp
using Microsoft.Extensions.Logging;
using Microsoft.Extensions.Logging.Abstractions;

ILogger logger = NullLogger.Instance;
ILogger<MyService> typedLogger = NullLogger<MyService>.Instance;
```

`NullLogger` ships in the `Microsoft.Extensions.Logging.Abstractions` package, the same package that defines
`ILogger`. A project that references `ILogger` already has it.

## Tests that verify logging: FakeLogger

Pass a `FakeLogger<T>` to the code under test, then assert on the records it captured. `FakeLogger` is in the
`Microsoft.Extensions.Diagnostics.Testing` package and the `Microsoft.Extensions.Logging.Testing` namespace.

Install the package in your test project:

```shell
dotnet add package Microsoft.Extensions.Diagnostics.Testing
```

This test replaces the `Verify` call in [Why mocking ILogger is fragile](#why-mocking-ilogger-is-fragile):

```csharp
using Microsoft.Extensions.Logging;
using Microsoft.Extensions.Logging.Testing;

var logger = new FakeLogger<OrderService>();
var service = new OrderService(logger);

service.PlaceOrder(42);

Assert.Equal(1, logger.Collector.Count);
Assert.Equal(LogLevel.Information, logger.LatestRecord.Level);
Assert.Equal("Order 42 placed", logger.LatestRecord.Message);
```

`LatestRecord` holds the last entry. It throws `InvalidOperationException` when nothing was logged.
`Collector.Count` is the number of entries. `Collector.GetSnapshot()` returns every entry in order.

```csharp
using Microsoft.Extensions.Logging.Testing;

var logger = new FakeLogger<OrderService>();
var service = new OrderService(logger);

service.PlaceOrder(42);
service.PlaceOrder(43);

IReadOnlyList<FakeLogRecord> records = logger.Collector.GetSnapshot();

Assert.Equal(2, records.Count);
Assert.Equal("Order 42 placed", records[0].Message);
Assert.Equal("Order 43 placed", records[1].Message);
```

Each `FakeLogRecord` exposes these members:

| Member                          | What it holds                                              |
| ------------------------------- | ---------------------------------------------------------- |
| `Level`                         | The `LogLevel` of the entry                                |
| `Message`                       | The formatted message                                      |
| `Id`                            | The `EventId`                                              |
| `Exception`                     | The logged exception, or `null`                            |
| `Category`                      | The logger category name                                   |
| `StructuredState`               | The state as string key and value pairs, or `null`         |
| `GetStructuredStateValue(key)`  | One template value, such as `"42"` for `"OrderId"`         |

## Code under test that takes ILoggerFactory

You do not need to mock `ILoggerFactory` either. Take this class, which creates its own logger:

```csharp
using Microsoft.Extensions.Logging;

public class OrderProcessor
{
    private readonly ILogger _logger;

    public OrderProcessor(ILoggerFactory loggerFactory) => _logger = loggerFactory.CreateLogger<OrderProcessor>();

    public void Process(int orderId) => _logger.LogInformation("Order {OrderId} processed", orderId);
}
```

Pass `NullLoggerFactory.Instance` when the test ignores logging.

```csharp
using Microsoft.Extensions.Logging.Abstractions;

var processor = new OrderProcessor(NullLoggerFactory.Instance);
```

To check the logs, build a factory around a `FakeLoggerProvider`. Every logger the factory creates writes to the
provider's `Collector`.

```csharp
using Microsoft.Extensions.Logging;
using Microsoft.Extensions.Logging.Testing;

var provider = new FakeLoggerProvider();
using var loggerFactory = LoggerFactory.Create(builder => builder.AddProvider(provider));
var processor = new OrderProcessor(loggerFactory);

processor.Process(42);

Assert.Equal("Order 42 processed", provider.Collector.LatestRecord.Message);
```

Moq1004 does not flag a mock of `ILoggerFactory`. The same advice applies.

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1004
var mock = new Mock<ILogger<MyService>>(); // Moq1004
#pragma warning restore Moq1004
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1004.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).

## FAQ

### Should I mock ILogger with Moq?

No. Use `NullLogger` to ignore logs or `FakeLogger` to check them. Moq1004 warns when you mock `ILogger` or
`ILogger<T>`.

### How do I verify that ILogger was called in a unit test?

Pass a `FakeLogger<T>` to the code under test. Assert on `LatestRecord` or `Collector` instead of calling
`mock.Verify(x => x.Log(...))`. See [Tests that verify logging](#tests-that-verify-logging-fakelogger).

### Why can't I Verify LogInformation with Moq?

`LogInformation` is an extension method. Moq can only intercept overridable members (interface, virtual, or
abstract). For a log call that is `Log<TState>`, and matching it needs `It.IsAnyType` matchers.

### Which package contains FakeLogger?

The `Microsoft.Extensions.Diagnostics.Testing` package. The type is in the `Microsoft.Extensions.Logging.Testing`
namespace, so write `using Microsoft.Extensions.Logging.Testing;`.

### How do I pass a logger when the test does not care about logs?

Use `NullLogger.Instance` or `NullLogger<T>.Instance` from `Microsoft.Extensions.Logging.Abstractions`.

### How do I turn off Moq1004?

Set `dotnet_diagnostic.Moq1004.severity = none` in `.editorconfig`, or wrap the line in
`#pragma warning disable Moq1004`. See [Suppress a warning](#suppress-a-warning).
