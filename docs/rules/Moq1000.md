# Moq1000: Sealed classes cannot be mocked

| Item     | Value   |
| -------- | ------- |
| Enabled  | True    |
| Severity | Warning |
| CodeFix  | False   |

---

No, Moq cannot mock a sealed class. Moq creates a subclass of the mocked type, and a sealed class cannot be
subclassed. Mock an interface the class implements, wrap the class behind your own interface, or use the real object.
Moq1000 reports the attempt at build time.

```csharp
public sealed class PaymentGateway
{
    public bool Charge(decimal amount) => true;
}

var mock = new Mock<PaymentGateway>(); // Moq1000
```

## Runtime error this rule prevents

Without the analyzer, the code compiles and the test fails when it runs. Moq throws `NotSupportedException` from the
`new Mock<T>()` call. You do not need to touch `.Object` or call `Setup` first. `Mock.Of<T>()` and
`MockRepository.Create<T>()` throw the same exception.

The message depends on your Moq version. Each text below comes from running the sample above on that version.

Moq 4.2.1510.2205 through 4.12.0 (ran 4.2.1510.2205, 4.5.30, 4.7.145, 4.8.2, 4.10.1, 4.11.0, and 4.12.0):

```text
Type to mock must be an interface or an abstract or non-sealed class.
```

Moq 4.13.0 through 4.15.2 (ran 4.13.0, 4.13.1, 4.14.7, and 4.15.2):

```text
Type to mock must be an interface, a delegate, or a non-sealed, non-static class.
```

Moq 4.16.0 through 4.20.72 (ran 4.16.0, 4.18.4, and 4.20.72). Moq puts the type name in the parentheses, without its
namespace:

```text
Type to mock (PaymentGateway) must be an interface, a delegate, or a non-sealed, non-static class.
```

All fourteen versions listed above threw `NotSupportedException`.

## Diagnostic message

```text
Sealed class '{0}' cannot be mocked
```

The rule replaces `{0}` with the type name, including its namespace. A `PaymentGateway` class in the `Shop` namespace
gives:

```text
Sealed class 'Shop.PaymentGateway' cannot be mocked
```

## What this rule flags

The rule flags two ways to create a mock of a sealed class: `new Mock<T>()` and `Mock.Of<T>()`. Extra arguments do not
change the result, so `new Mock<PaymentGateway>(MockBehavior.Strict)` is flagged too.

```csharp
var mock = new Mock<PaymentGateway>(); // Moq1000
var gateway = Mock.Of<PaymentGateway>(); // Moq1000
```

Sealed records and sealed framework types such as `string` count as sealed classes.

The rule does not flag these cases:

- **`MockRepository.Create<T>()` and `MockRepository.OneOf<T>()`.** Moq still throws at run time. Check these calls
  yourself.
- **Generic helpers.** A method such as `Mock<T> Make<T>() => new Mock<T>()` is not flagged when you call it with a
  sealed class. Moq still throws at run time.
- **Arrays.** `new Mock<int[]>()` is not flagged. Moq still throws at run time.
- **Delegates.** Moq can mock them. See [Delegates are not flagged](#delegates-are-not-flagged).
- **Structs, enums, and `Nullable<T>`.** The compiler rejects them first with CS0452, because `Mock<T>` requires a
  reference type.

The rule is a warning by default. If your project treats warnings as errors, Moq1000 fails the build.

## How to fix

Pick the first fix that fits your case.

| Your case | Fix |
| --------- | --- |
| The class already implements an interface, or you can add one | [Mock the interface](#mock-an-interface-the-class-implements) |
| You do not own the class | [Wrap it behind your own interface](#wrap-the-sealed-type-behind-your-own-interface) |
| The class is cheap to create and has no side effects | [Use the real object](#use-the-real-object) |
| You own the class and want to mock it directly | [Remove `sealed`](#unseal-the-class-when-you-own-it) |

### Mock an interface the class implements

Mock the interface, and leave the class sealed. If the class has no interface and you own it, add one.

```csharp
public interface IPaymentGateway
{
    bool Charge(decimal amount);
}

public sealed class PaymentGateway : IPaymentGateway
{
    public bool Charge(decimal amount) => true;
}

var mock = new Mock<IPaymentGateway>();
mock.Setup(x => x.Charge(It.IsAny<decimal>())).Returns(false);
```

Your code under test must depend on `IPaymentGateway`, not on `PaymentGateway`.

### Wrap the sealed type behind your own interface

Use a wrapper when you cannot change the sealed type. Here `VendorClient` stands in for a sealed class from a
third-party package.

```csharp
public sealed class VendorClient
{
    public bool Charge(decimal amount) => true;
}

public interface IPaymentClient
{
    bool Charge(decimal amount);
}

public sealed class ThirdPartyPaymentClient : IPaymentClient
{
    private readonly VendorClient _client = new();

    public bool Charge(decimal amount) => _client.Charge(amount);
}

var mock = new Mock<IPaymentClient>();
mock.Setup(x => x.Charge(It.IsAny<decimal>())).Returns(false);
```

Production code uses `ThirdPartyPaymentClient`. Tests mock `IPaymentClient`. The same pattern fixes non-virtual and
static members. See [Wrap a sealed, static, or third-party type](Moq1200.md#wrap-a-sealed-static-or-third-party-type)
on the Moq1200 page.

### Use the real object

You do not need a mock for a type that only holds data. Create a real instance. This fits sealed records, value-like
types, and exceptions you can construct.

```csharp
public sealed record Money(decimal Amount, string Currency);

public interface IPriceCalculator
{
    Money Total();
}

var price = new Money(10m, "USD");

var mock = new Mock<IPriceCalculator>();
mock.Setup(x => x.Total()).Returns(price);
```

### Unseal the class when you own it

Remove `sealed`, and mark the members you set up as `virtual`. Moq can only intercept overridable members, and
[Moq1200](Moq1200.md) reports a `Setup` on any other member.

```csharp
public class PaymentGateway
{
    public virtual bool Charge(decimal amount) => true;
}

var mock = new Mock<PaymentGateway>();
mock.Setup(x => x.Charge(It.IsAny<decimal>())).Returns(false);
```

This changes your production design to suit a test. Prefer an interface when you can.

## Example: SqlException

`SqlException` is a common case. In Microsoft.Data.SqlClient 6.1.1 it is sealed and has no public constructor. You
cannot mock it, and you cannot create one with `new`.

```csharp
var mock = new Mock<SqlException>(); // Moq1000
```

Do not try to produce a `SqlException` in the test. Put data access behind an interface, and have the mock throw an
exception you can construct. `SqlException` derives from `DbException`, so code that catches `DbException` handles
both.

```csharp
using System.Data.Common;

public interface IOrderStore
{
    void Save(int orderId);
}

public sealed class StoreUnavailableException : DbException
{
    public StoreUnavailableException(string message) : base(message) { }
}

public class OrderService
{
    private readonly IOrderStore _store;

    public OrderService(IOrderStore store) => _store = store;

    public bool TrySave(int orderId)
    {
        try
        {
            _store.Save(orderId);
            return true;
        }
        catch (DbException)
        {
            return false;
        }
    }
}

var store = new Mock<IOrderStore>();
store.Setup(x => x.Save(It.IsAny<int>())).Throws(new StoreUnavailableException("Connection lost"));

var service = new OrderService(store.Object);
bool saved = service.TrySave(42); // false
```

You can find code that builds a `SqlException` through reflection on its non-public constructors. Those constructors
are not part of the public API, so that code can break when you update the package.

## Delegates are not flagged

Every delegate type is sealed, but Moq can mock delegates. Moq1000 does not flag them.

```csharp
var func = new Mock<Func<int>>();
func.Setup(f => f()).Returns(42);

int result = func.Object(); // 42
```

## Suppress a warning

Suppressing Moq1000 does not stop the runtime exception. The test still throws `NotSupportedException`.

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1000
var mock = new Mock<PaymentGateway>();
#pragma warning restore Moq1000
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1000.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).

## FAQ

### Can Moq mock a sealed class?

No. Moq creates a subclass of the mocked type, and a sealed class cannot be subclassed. Moq1000 reports it at build
time.

### What does "Type to mock must be an interface, a delegate, or a non-sealed, non-static class" mean?

You asked Moq to mock a type it cannot subclass, such as a sealed class. Mock an interface instead, or use the real
object. Moq 4.16.0 and later add the type name in parentheses after `Type to mock`. See [How to fix](#how-to-fix).

### What does "Type to mock must be an interface or an abstract or non-sealed class" mean?

It is the same error from Moq 4.12.0 and older. See
[Runtime error this rule prevents](#runtime-error-this-rule-prevents).

### How do I mock a sealed class I do not own?

Put it behind your own interface, and mock the interface. See
[Wrap the sealed type behind your own interface](#wrap-the-sealed-type-behind-your-own-interface).

### Can Moq mock a delegate?

Yes. Delegates are sealed, but Moq supports them, and Moq1000 does not flag them.

### How do I mock SqlException?

You cannot. It is sealed. Hide data access behind an interface, and have the mock throw an exception your code
handles. See [Example: SqlException](#example-sqlexception).

### Does suppressing Moq1000 fix the error?

No. Suppression hides the warning. The test still throws `NotSupportedException` at run time.
