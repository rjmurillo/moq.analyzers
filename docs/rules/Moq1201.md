# Moq1201: Setup of async methods should use `.ReturnsAsync` instance instead of `.Result`

| Item     | Value |
| -------- | ----- |
| Enabled  | True  |
| Severity | Error |
| CodeFix  | False |

---

Moq provides the `.ReturnsAsync()` method for mocking async methods. Use `.ReturnsAsync()` instead of putting
`.Result` inside the `Setup` expression.

This rule applies only when your project references a Moq version older than 4.16.0. The analyzer does not report
Moq1201 for Moq 4.16.0 and later. Moq 4.16.0 added support for `.Result` in setup expressions. See the
[Moq 4.16.0 changelog](https://github.com/devlooped/moq/blob/v4.18.4/CHANGELOG.md#4160-2021-01-16).

Without the analyzer, the flagged code compiles. Moq 4.15.2 then throws `NotSupportedException` from the `Setup` call
when the test runs. Moq abbreviates the expression as shown:

```text
System.NotSupportedException: Unsupported expression: ... => ....Result
Non-overridable members (here: Task<string>.get_Result) may not be used in setup / verification expressions.
```

## Examples of flagged code

This sample references Moq 4.15.2.

```csharp
public class AsyncClient
{
    public virtual Task<string> GetAsync() => Task.FromResult(string.Empty);
}

var mock = new Mock<AsyncClient>();
mock.Setup(c => c.GetAsync().Result).Returns("value"); // Moq1201
```

The build reports this error:

```text
error Moq1201: Setup of async method 'GetAsync' should use ReturnsAsync instead of .Result
```

## How to fix

```csharp
public class AsyncClient
{
    public virtual Task<string> GetAsync() => Task.FromResult(string.Empty);
}

var mock = new Mock<AsyncClient>();
mock.Setup(c => c.GetAsync()).ReturnsAsync("value");
```

This fix works on Moq 4.15.2 and on Moq 4.20.72. For `ValueTask`, `null`, and methods with parameters, see
[How to set up async methods in Moq](../moq-returnsasync.md).

If your project references Moq 4.16.0 or later, the flagged line works as written and the analyzer does not report it.

## Suppress a warning

To suppress a single violation, add preprocessor directives to your source file
that disable and then re-enable the rule.

```csharp
#pragma warning disable Moq1201
mock.Setup(c => c.GetAsync().Result).Returns("value"); // Moq1201
#pragma warning restore Moq1201
```

To disable the rule for a file, folder, or project, set its severity to `none`
in the
[configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.{cs,vb}]
dotnet_diagnostic.Moq1201.severity = none
```

For more information, see
[How to suppress code analysis warnings](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/suppress-warnings).
